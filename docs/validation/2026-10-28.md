# Sharing, privacy and update improvements

Scope: iPhone share sheet; expiring verification codes; per-device send/receive/image/code preferences; release notices and an AltStore/SideStore source; local-history encryption and group-key rotation on device removal. No new per-transfer receipt notifications were added.

## Behavior and compatibility

- Device preferences live on the device on which they are changed. A new clip carries its permitted recipients when a send restriction applies, so another current-version peer cannot accidentally relay it to an excluded device. Receiving also checks the original source's local policy. Live sending, incoming-image announcements and catch-up transfers respect these preferences. Already stored copies on other devices are not recalled when a preference changes.
- Restricted clips are sent only to peers advertising `policy1`. Earlier versions cannot safely enforce their recipient list. Updating the destination is required for iPhone's explicit share-to-device flow.
- Verification-code clips expire 180 seconds after their original timestamp, including pinned clips. Expiration propagates deletion tombstones; receiving, forwarding and catch-up independently reject expired codes. A code more than 60 seconds in the future is rejected rather than retained indefinitely. Copying a code from history remains a local code copy and never turns it into an ordinary unlimited-lifetime clip.
- On iOS, clipboard expiration uses the system's expiration date and disables Universal Clipboard propagation for that code. Mac and Windows clear the clipboard only if its change counter and text still match the original write. Android additionally checks Nearclip's item marker; if Android denies background clipboard access, Nearclip leaves the clipboard alone. The history and code-copy actions still expire. Apps must be running for app-managed clipboard cleanup; history expiration is enforced again on startup.
- Persistent history, images, large text side files and engine state use AES-256-GCM under an independent device-local key. The key normally uses Keychain on Apple platforms, Keystore wrapping on Android and DPAPI on Windows. Apple retains its existing file-secret fallback when Keychain initialization is unavailable; that fallback and CLI/test file-secret stores do not protect the key separately from app files. Legacy plaintext is atomically migrated. Version 1.1 cannot read the migrated 1.2 store; no plaintext rollback copy is retained. File names are authenticated to reject file substitution; decryption failures do not replace history with an empty file.
- Native preview and sharing APIs need readable image files. These are materialized in private temporary directories, removed on item deletion and on normal shutdown (Android clears its temporary directory at the next startup and regenerates clipboard image views on demand, including legacy image URIs). This does not encrypt the operating system's clipboard, screenshots or arbitrary backups made before migration.
- Removing a device sends a fresh group key over established encrypted sessions to the remaining current-version peers. The removed device receives no new key. The old key is not retained as an offline recovery credential. Remaining devices that were offline, unreachable without the removed device, or running a version without `rekey1` must be paired again; the removal dialog discloses this before proceeding. Concurrent independent rotations are not automatically reconciled; re-pairing restores a split group.
- The iOS share extension receives one text, link or image, lists allowed destinations and owns a separate temporary engine. It never opens the main app's live store. Pairing context (without history) is passed through the common Keychain group. PNG/JPEG data is sent without a full decode; other formats are converted with a bounded thumbnail size. Legacy providers vending a UIKit image object are also supported. Keep the extension enabled when signing the IPA. Real personal-team/SideStore entitlement rewriting still needs installation acceptance.
- Sharing works on the LAN and can borrow the main app's remote proxy while that process is available. iOS does not allow the extension to keep the main app's Tailscale process alive indefinitely. If that proxy has stopped, open the main app for remote sending. A failed share does not claim that the destination copied it.
- Mac direct-download and Android settings check GitHub releases, at most once a day automatically, with an explicit retry. Store updates remain managed by their stores. No downloaded executable is launched automatically. The published source is generated from the IPA's real bundle version, build number, size, digest, entitlements and privacy declarations. Website deployment regenerates it on release publication/edit.

## Verification

Local results on the 1.2 implementation:

- C# engine: 59 tests passed, including legacy migration, authenticated storage, corrupt-file preservation, expiry, recipient filtering, online key rotation and offline-key rejection.
- Kotlin engine: 33 tests passed; Android debug and optimized release APK assembly, debug lint and release lint passed. Only the pre-existing sensitive-notification resource-lookup warning remains.
- Real localhost cross-language peers: 48 pairing/text/image/catch-up/mesh/remote/re-add scenarios passed, plus 12 policy, isolated share-engine catch-up and online/offline rotation scenarios across every ordering of Swift, Kotlin and C#.
- Verification-code expiry was observed after waiting 190 real seconds: all three engines deleted the code, retained ordinary history, and did not restore the expired code after restart. No code was auto-applied.
- Website browser smoke checks: 244 passed. Source-generation metadata and permission checks: 6 passed.
- [Native CI run 40706575406](https://github.com/ivLis-Studio/nearclip/actions/runs/40706575406), on product commit `53cc8e3`, passed every job. It built the Mac and Windows apps, passed 23 Swift tests, archived the universal iPhone/iPad app with its extension, and packaged the ad hoc IPA. On the iOS 26.2 simulator, onboarding, pairing, history catch-up, sending, persisted per-device controls and URL/text/image sharing through UIKit’s real system share sheet passed. The harness independently checked all three payloads at the receiving peer after the UI completed.

Additional local acceptance after the external SDK drive became available:

- Xcode 27: all 23 Swift tests passed locally. iOS 26.5 manual acceptance used Device Hub and actual native apps; the local XCTest launch service could not bootstrap, so it is not counted as a local automated UI pass.
- The iPhone share extension sent a URL, plain text and a legacy `public.image`/`UIImage` item to a C# peer. The received PNG was 328 bytes with SHA-256 `91917b6d4fc747d1009ce3f9d455efe4f2e561e259ffcd8020d472ef77977d27`. The original iPhone app caught up with all three of its own items afterward.
- A paired Android app did not receive those items selected for C#, while a new unrestricted C# positive-control message did arrive. Its image category remained empty. This exercised recipient restrictions through a real three-device group.
- Android 16: the app displayed existing 1.1 history after upgrading; the stored history had the `NCV1` encryption envelope. Tests ran with a read-only emulator overlay so the original QA virtual device was preserved.
- Android native device settings: receiving off rejected a new remote item and retained existing history. Sending off excluded the C# peer; sending on delivered a new item without forwarding the earlier restricted item, including after it reached the iPhone through the mesh. Switch rows now expose the label with the toggle and respond to the whole row.
- Browser-specific Safari launch/navigation acceptance was not counted; system sharing was verified with UIKit’s real share sheet. Personal-team/SideStore/AltStore re-signing and physical-device installation remain unverified.

Acceptance payloads were generated test fixtures. Local logs are kept outside the repository.

## Reproducing the checks

- `dotnet run --project windows/tests/Nearclip.Core.Tests`
- In `android/`, run `./gradlew :core:test :app:assembleDebug :app:assembleRelease :app:lintDebug :app:lintRelease` with an available Android SDK.
- `swift test --package-path apple/NearclipKit` with Xcode selected.
- `python3 tools/interop/run.py --impl swift=/path/to/nearclip-cli --only swift,kotlin,dotnet --scenarios pair,code,transfer,mesh,remote,readd`
- `python3 tools/interop/privacy.py --swift /path/to/nearclip-cli` (add `--expiry` for the real-time expiration check).
- `python3 -m unittest discover -s tools/release -p test_altstore_source.py`
- Native app builds, Swift tests, simulator UI results and a test IPA are retained by the **Native validation** GitHub workflow. The simulator-only `NearclipShareHarness` opens UIKit's real system share sheet; it is not linked into or embedded in the release app.

Production release assets and Store submissions have not been replaced by this validation run.
